# BRIEF 05 — QA the Tantei redesign

**Agent:** Codex, gpt-5.6-sol, medium effort
**Repo:** the repository root

---

## Situation

Another agent has just implemented a visual redesign of NoWatermark.fyi, a
working static site. You are the QA gate. **Assume the implementation is
wrong until you have evidence it is right.** Your job is to find what broke,
not to admire what was built.

Read first:
1. `.design/TANTEI-SPEC.md` — what was supposed to be built.
2. `.briefs/01-build.md` — what the builder was told.
3. `.reports/01-build-report.md` — what the builder claims it did.
4. `README.md` — the product's architecture and honesty rules.

Then check the git diff of the redesign commit to see what actually changed.

## Verification checklist

Work through every item. Record evidence — a command and its output — for each.
Do not mark anything as passing on inspection alone where a command can prove it.

### A. Build and tests
```bash
pnpm build            # must succeed
pnpm test             # 76 tests must pass
```
If any test fails, that is a P0. The engine was fully working before this
redesign; a failure means the redesign broke it.

### B. The hard rule — no Japanese
```bash
grep -rlP '[\x{3000}-\x{30FF}\x{4E00}-\x{9FFF}\x{FF00}-\x{FFEF}]' src/
```
Must return nothing. Any hit is a P0.

### C. Zero-JS guides (the SEO engine)
```bash
pnpm build
grep -o 'src="/_astro/[^"]*"' dist/guides/what-is-synthid/index.html
```
Must return nothing. A guide page shipping React is a P1.

### D. Static HTML still carries the content
For `dist/exif-remover/index.html` and `dist/guides/what-is-synthid/index.html`,
confirm each still has: a unique `<title>`, a `<meta name="description">`, a
canonical link, an `<h1>`, JSON-LD, and real body copy. Crawlers must not need
JavaScript.

### E. Contrast — WCAG AA
This is a release gate in the spec. Serve the built site and measure computed
styles in a real browser rather than eyeballing hex values:
```bash
pnpm preview --port 4321
```
Walk the homepage, a tool page, a guide, and `/methodology` in both light and
dark. For every text node, compute the contrast ratio of its colour against its
effective background. Report anything under 4.5:1 (or under 3:1 for text at
18.66px+ bold). Check **both themes** — a common failure is a colour defined
only inside a `@media (prefers-color-scheme: dark)` block.

### F. The honesty rule
This is the product's whole differentiator and the highest-value thing to break.
- `src/lib/signals.ts` and `STATUS_LABEL` in `src/lib/types.ts` must be
  unchanged. Confirm via git diff.
- The four status strings must be exactly: `Detected`, `Not detected`,
  `Unknown`, `Unable to verify`.
- A signal with status `unable_to_verify` must render as the inked-out panel
  and must be visually distinct from a cleared/removed result. Verify in the
  browser, not in the source.
- No page may claim the tool removes SynthID or statistical text watermarks.

### G. The tool still works end to end
Drive a real browser. Sample files with known metadata are available:
```bash
node tests/fixtures/generate.ts     # writes tests/fixtures/samples/
```
`samples/loaded.jpg` contains GPS 51.507N 0.128W, device "NoWatermark Test
Fixture Camera", software "ChatGPT", a C2PA manifest, XMP and IPTC.

Verify: upload → scan finds those signals → clean → the before/after report
shows them removed → the download link is a local `blob:` URL.

### H. Zero file-processing network requests
With the browser network panel recording, scan and clean a file. **No request
may carry file contents, a file hash, a filename, or extracted metadata.** Only
static assets, the worker script, and local `blob:` URLs are permitted. This is
the product's core promise; treat any violation as P0.

### I. Offline operation
Set the browser to offline after the page loads, then scan, clean and download.
All three must work. This is the strongest proof the architecture held.

### J. Responsive
Check the homepage and a tool page at 375px wide. The spec requires the panel
grid to genuinely reflow to a single column, not scale down. Confirm the page
body never scrolls horizontally.

### K. Accessibility basics
Keyboard-reachable file input, visible focus states, the ARIA live region still
announcing scan phases, and no status conveyed by colour alone.

## Output

Write `.reports/05-qa-report.md`:

- **Verdict**: SHIP or DO NOT SHIP, in the first line.
- **Findings table**: each with severity (P0 blocks release, P1 must fix before
  launch, P2 should fix, P3 polish), the file and line, what you observed, the
  command or measurement that proves it, and a suggested fix.
- **Checklist results**: every item A–K with its evidence.
- **What you could not verify** and why. Be explicit about gaps — an honest
  "not tested" is worth more than an assumed pass.

Rank findings most severe first. Do not fix anything yourself unless it is a
one-line, zero-risk correction — this is a review pass, and the value is in an
accurate report. If you do fix something, list it separately under "fixed in
place".
